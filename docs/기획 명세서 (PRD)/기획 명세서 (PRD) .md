# 기획 명세서 (PRD)

# 핵심 요약

- **배경**: 반려동물 상실 경험자의 상당수가 상실감·우울감을 겪지만, 생전에 이별을 준비하는 과정은 마련되어 있지 않음
- **문제**: 보호자의 77.8%가 이별을 이미 인지하고 있으나, 정서적 준비 방법을 몰라 막막함을 느낌(55.6%)
- **해결 방향**: 생전 버킷리스트 + 사후 추억리스트 제안, 활동 후 기록(글·사진)으로 의미 있는 경험을 축적
- **검증 가설**: 신규 가입자의 25% 이상이 가입 후 리스트를 1회 이상 완료할 것 (기준선: 소비자 앱 활성화율 대리 지표, 실측 후 조정)
- **MVP 범위**: 버킷/추억 리스트+기록, 메모리, 생전-사후 전환, 온보딩/로그인/탈퇴 (개·고양이 보호자 대상)
- **검증 방법**: GA4 이벤트 트래킹으로 완료율(핵심 KPI) + 필드별 관여도(선행지표) + 단계별 퍼널(보조지표)을 계측, 1차 배포 후 실측 데이터로 목표치 재조정

- 975명을 대상으로 한 연구에서 32.6%가 반려동물간의 이별을 경험했으며, 이들 중 **21%는 반려동물의 죽음을 가장 고통스러운 경험**으로 생각 ([출처](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0339213))
- 반려동물 상실 경험자의 55%가 중등도 이상의 병리적 슬픔을 경험했으며, 52%는 주요 우울증 기준, 40%는 중등도 불안, 32%는 임상적으로 유의한 불면증 수준을 보임 ([출처](https://www.maum-sopoong.or.kr/infor_story/52448))

---

- 펫로스로 인한 수면 장애·식사 변화 등이 2주 이상 지속되고 **일상 기능까지 저하**될 경우, 단순한 슬픔을 넘어 치료가 필요한 상태로 이어질 수 있음 ([출처](https://health.chosun.com/site/data/html_dir/2026/03/05/2026030504125.html))
- 반려동물과의 이별 시 나타나는 뇌의 반응은 **가까운 가족을 잃었을 때와 유사**하며, 애착·감정과 관련된 뇌 영역에서도 **인간관계 상실과 유사한 활성화 패턴**이 나타남 ([출처](https://www.sciencetimes.co.kr/nscvrg/view/menu/251?searchCategory=223&nscvrgSn=259808))

약 25%는 찾고 싶은 충동, 회피, 분노, 불안, 우울 등을 겪음 ([출처](https://pubmed.ncbi.nlm.nih.gov/8032709/))

# 3. 문제 정의

## 3-1. 원인 분석

---

### **문제 현상**

**반려동물과의 이별 이후 상당수의 보호자가 강한 상실감과 우울감을 경험한다.**

#### **원인 흐름 A**

> **Why1. 왜 강한 상실감과 우울감을 경험하는가?**
반려동물을 단순한 동물이 아닌 가족·친구와 같은 중요한 정서적 관계의 대상으로 인식하는데, 함께했던 관계가 갑자기 단절되고 일상적인 교감과 돌봄의 대상이 사라지기 때문

**Why 2. 왜 관계의 단절과 공백을 받아들이는 데 어려움을 겪는가?**
이별 이후에도 반려동물에 대한 그리움·후회·죄책감 등 미처 정리되지 않은 감정이 남기 때문

**Why3. 왜 이러한 감정을 (충분히) 정리하지 못하는가?**
반려동물이 살아있는 동안 이별을 준비하거나 상실을 받아들이는 과정이 충분히 마련되어 있지 않기 때문
> 

**근본 원인:** 반려동물이 **살아있는 동안 이별을 준비하거나 상실을 받아들이는 과정이 충분히 마련되어 있지 않기 때문에**, 반려동물과의 이별 이후 상당수의 보호자가 강한 상실감과 우울감을 경험한다.

#### **원인 흐름 B**

> **Why1. 왜 강한 상실감과 우울감을 경험하는가?**
반려동물과의 이별로 인한 슬픔을 충분히 공감받거나 위로받지 못해, 상실의 감정을 해소하기 어렵기 때문

**Why2. 왜 공감과 위로를 충분히 받을 수 없는가?**
반려동물과의 이별을 직접 경험하지 않은 주변 사람에게는 상실의 깊이를 충분히 이해받기 어렵고, 비슷한 경험을 한 사람과 연결되어 공감과 위로를 나눌 기회도 부족하기 때문

**Why3. 왜 비슷한 경험을 한 사람들과 충분히 공감과 위로를 나눌 기회가 부족한가?**
기존 반려동물 커뮤니티는 ‘지금 반려동물을 키우는 사람’ 위주로 운영돼서  펫로스 경험자가 자신의 감정을 공유할 자리(앱 서비스, 커뮤니티 등) 자체가 거의 없기 때문
> 

**근본 원인:** 기존 반려동물 커뮤니티는 ‘지금 반려동물을 키우는 사람’ 위주로 운영돼서 펫로스 경험자가 자신의 감정을 공유할 자리가 거의 없기 때문에, 반려동물과의 이별 이후 심리적 고통이 장기간 지속되고 있다.

## 5-2. 해결 방안

---

생전에는 반려동물과 함께 할 수 있는 버킷 리스트를, 사후에는 반려동물을 추억하는 리스트를 제안하고, 각 활동을 사진과 이야기로 기록할 수 있도록 함

<aside>

**설계 근거 (기대 효과)**

- **생전 활동 제안(버킷리스트)**
    - 좋은 경험을 의도적으로 만들고 충분히 느끼는 것이 도움이 된다는 연구를 참고 ([출처](https://iaap-journals.onlinelibrary.wiley.com/doi/10.1111/aphw.70134))
- **기록으로 감정 완화**
    - 감정을 글로 표현하는 것이 슬픔·우울 완화에 도움이 된다는 연구를 참고 ([출처](https://journals.sagepub.com/doi/10.1177/10497315251371566))
    - 자체 설문조사 결과, 응답자의 81.8%가 '함께한 순간을 기록으로 남긴다'고 응답
- **사후 추억 기록을 통한 충분한 애도**
    - 추억을 이어가는 것이 슬픔 조절에 도움이 될 수 있다는 연구를 참고 ([출처](https://pmc.ncbi.nlm.nih.gov/articles/PMC11776356/))
</aside>

## 5-3. 핵심 가치

<aside>

단, 이별 이후의 수용과 추억의 지속은 단기간에 측정하기 어려워, 이번 검증 범위에서는 제외하고 장기적인 성과 지표로 설정함

</aside>

## 5-4. 검증 가능한 가설

---

### **이번 MVP로 검증할 가설**

> 이별 준비가 필요한 반려동물 보호자에게 생전부터 사후까지 기록·관리하는 서비스를 제공한다면, **신규 가입자의 25% 이상이 가입 후 리스트를 1회 이상 완료할 것**이다.
> 

### **기준선(25%) 설정 근거**

펫로스·기록관리형 앱의 활성화 지표는 확인되지 않아, 가장 근접한 대리 지표로 **모바일 앱 일반 활성화율을 참고**함

- **전체 앱 평균**: 카테고리 구분 없이 조사한 [출처](https://www.plotline.so/blog/activation-rates-mobile-apps-by-industry)에 따르면 **평균 34%, 중앙값 25%**
- **카테고리별 구분**: [출처](https://scilla.studio/insights/activation-rate/)는 B2B SaaS(25~40%)와 **소비자 앱(15~30%)**을 구분해서 제시.
본 서비스는 개인 소비자 대상이며 "리스트 1회 완료"는 핵심 가치를 실제로 경험하는 진짜 활성화(true activation)에 해당하므로, 소비자 앱 구간(15~30%)이 적용 대상
- **두 자료의 수렴**: 전체 평균 중앙값(25%)이 소비자 앱 구간(15~30%) 근처에 위치해, 서로 다른 두 자료가 비슷한 범위로 수렴함을 확인
- **수치의 한계**: 위 수치들은 정의 방식과 관찰 기간에 따라 편차가 크고 산업 간 직접 비교가 어려운, 정식 데이터가 아닌 실무 추정치임([출처](https://pmtoolkit.ai/benchmarks/activation-rate-benchmarks))

⇒ 이에 소비자 앱 구간(15~30%) 내 중앙값 수준인 **25%**를 기준선으로 채택함
단, 해당 수치는 초기 기준선으로 활용하고, 출시 후 실측 데이터를 확보하여 2차 PRD에서 KPI 및 목표치를 조정할 수 있음

# 7. 데이터 트래킹 계획 (GA4 또는 기타 트래킹 툴)

## 7-1. 트래킹 설계 원칙

---

- 핵심 KPI 및 선행·보조지표를 실제 GA4 이벤트로 측정할 수 있도록, 화면설계서(Onboard~Profile)의 화면 ID 및 사용자 행동 단위로 이벤트를 매핑함
- 이벤트명은 GA4 이벤트명 규칙(영문자로 시작, 영문자·숫자·언더스코어 사용, 40자 이하, 예약어 사용 금지)을 준수하며, 프로젝트 내 일관성을 위해 소문자 `snake_case` 형식으로 통일함
- GA4 권장 이벤트가 존재하는 행동은 해당 이벤트명을 우선 사용함

| 구분 | 설계 원칙 |
| --- | --- |
| **트래킹 범위** | **핵심 KPI 기록 1회 이상 완료율, 
선행지표** 기록 수정 화면 진입 후 필드별 1회 이상 클릭률, 
**보조지표** 기록 화면 진입률·리스트 항목 추가 클릭률을 GA4 이벤트로 계측 |
| **이벤트 매핑** | 화면설계서(Onboard~Profile)의 실제 화면 ID 및 버튼/행동 단위로 이벤트 매핑 |
| **사용자 식별** | 로그인 완료 이후 `user_id`를 GA4 User-ID로 일관되게 설정하며, 개별 이벤트 파라미터에는 반복 기재하지 않음 |
| **탈퇴 사용자 처리** | 회원탈퇴 시 계정 및 서비스 데이터는 삭제하며, 분석 로그는 별도로 유지함
동일 카카오 계정으로 재가입하더라도 신규 사용자로 처리하며 기존 서비스 데이터와 연결하지 않음 |
| **이벤트 발생 기준** | 단순 행동은 UI 클릭 시점, 데이터 생성·저장이 필요한 행동은 저장 성공 시점에 이벤트 발생 |
| **저장 성공 기준 이벤트** | `list_item_create`, `record_complete` 등은 버튼 클릭이 아닌 실제 데이터 저장 성공 시점을 기준으로 측정 |

## 7-3. 핵심 지표 산출 공식

---

#### **핵심 KPI - 기록 1회 이상 완료율**

```
핵심 KPI =
  COUNT(DISTINCT user_id
           WHERE record_complete 1회 이상 발생)
  ÷
  COUNT(DISTINCT user_id
           WHERE sign_up 발생)
  × 100
```

#### **선행지표 - 기록 수정 화면 진입 후 필드별 1회 이상 클릭률**

```
선행지표 =
  COUNT(DISTINCT user_id 
           WHERE record_field_interact 발생)
  ÷
  COUNT(DISTINCT user_id 
           WHERE record_edit_view 발생)
  x 100
```

`field_name` 파라미터를 기준으로 **기록 수정 화면에 진입한 사용자 중 각 필드를 1회 이상 클릭한 사용자 비율**을 확인한다.

## 7-4. 퍼널 분석 설계

---

완료율이라는 단일 지표만으로는 **사용자가 어느 단계에서 이탈했는지 파악하기 어렵기 때문에**, 기록 완료까지의 주요 행동을 단계별 퍼널로 분석함

- **추천 항목 이용:** 서비스가 미리 제공한 항목을 선택하는 방식으로, 무엇을 작성할지 고민하는 과정이 없어 상대적으로 진입 장벽이 낮음
- **직접 작성:** (+) 버튼을 통해 사용자가 직접 항목을 작성하는 방식으로, 무엇을 작성할지 결정하는 과정이 추가되어 상대적으로 진입 장벽이 높음
- **퍼널 분리:** 두 경로를 하나의 퍼널로 측정할 경우 경로별 이탈 지점을 구분하기 어려우므로, **추천 항목 이용 퍼널 / 직접 작성 퍼널**로 분리하여 단계별 전환율과 이탈 지점을 측정

#### **추천 항목 이용 퍼널** - 서비스가 제공한 기존 리스트 항목을 완료하는 경로

```
sign_up
→ onboarding_complete
→ list_view
→ list_item_row_click
→ record_edit_view
→ record_field_interact
→ record_complete
```

#### **직접 작성 퍼널** - 사용자가 신규 항목을 직접 작성하는 경로, 별도 관리

```
sign_up
→ onboarding_complete
→ list_view
→ list_add_button_click
→ list_item_create
→ list_item_row_click
→ record_edit_view
→ record_complete
```

#### **이탈 구간별 해석**

| 이탈 구간 | 이벤트 흐름 | 해석 |
| --- | --- | --- |
| 가입 및 온보딩 | `sign_up`→ `onboarding_complete` | 가입 및 반려동물 정보 입력 과정에서의 입력 부담 |
| (+) 버튼 클릭 → 신규 항목 저장 | `list_add_button_click` → `list_item_create` | 무엇을 작성할지에 대한 고민·입력 부담 |
| 리스트 항목 클릭 → 기록 수정 화면 진입 | `list_item_row_click` → `record_edit_view` | 화면 전환/기술적 문제 가능성 |
| 기록 수정 화면 진입 → 필드 클릭 | `record_edit_view` → `record_field_interact` | 기록 작성에 대한 초기 진입 부담, 화면 이해도 문제 |
| 필드 클릭 → 기록 완료 | `record_field_interact` → `record_complete` | 작성 난이도·입력 부담·저장 UX 문제 가능성 |

## 7-5. 트래킹 한계

---

GA4 이벤트 트래킹만으로는 **실제 오프라인 행동이나 사용자의 심리적 변화까지 직접 측정하기 어렵기 때문에**, 다음과 같은 한계를 고려하여 데이터를 해석함

- **기록 완료 이벤트의 한계**
    - `record_complete`는 사용자가 **앱 내에서 기록을 완료한 행동**만을 의미
    - 산책, 사진 촬영 등 **실제 오프라인 활동 수행 여부까지 확인할 수 없으므로**, 기록 완료가 실제 행동 수행을 의미한다고 단정하지 않음
    - 이는 **5-3 검증 한계와 동일한 맥락**으로 해석함
- **심리적 변화 측정의 한계**
    - 이별 준비에 대한 인식이나 상실감 완화와 같은 **심리적 변화는 GA4 이벤트만으로 측정하기 어려움**
    - 해당 변화는 **사용 전·후 설문 및 정성 인터뷰**를 통해 별도로 확인함
- **파라미터 구현의 한계**
    - 정의한 이벤트 및 파라미터는 **1차 배포 전 개발팀과 실제 구현 가능 여부를 재확인**
    - `char_count`, `fail_reason` 등 세부 데이터가 필요한 파라미터는 **구현 난이도와 분석 필요성에 따라 우선순위를 조정**할 수 있음
