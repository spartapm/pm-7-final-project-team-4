## 3. 계정 정책

### 3-1. 계정 단위

- 인증 수단은 **카카오 소셜 로그인 단일**이며 이메일/비밀번호 가입 없음
- 온보딩에서 등록된 반려동물의 **종·이름·나이는** 프로필에서 **수정  가능**
- **1 계정 = 1 반려동물**이며 다중 등록 불가
    - MVP(ver.1)에만 해당되는 사항으로, 추후에 늘어날 가능성이 있음

### 3-2. 로그인 및 분기

| 조건 | 진입 화면 |
| --- | --- |
| 세션 유효 (기존 유저) | Home-01 (해당 유저의 현재 모드) |
| 세션 만료 + 온보딩 정보 有 | Onboard-01(로그인)→ Home-01 |
| 세션 만료 + 온보딩 정보 無 | Onboard-01(로그인) → Onboard-02(온보딩) → Home-01 |
| 로그인 실패 | Onboard-01 유지 후 재시도 |
- 온보딩 정보 보유 여부의 판단 기준은 **반려동물 프로필 데이터 존재 여부**
    - 최초 온보딩(Onboard-02) 완료 이후 프로필에 반려동물 프로필 데이터 기록됨

### 3-3. 세션 정책

| 항목 | 설명 | 비고 |
| --- | --- | --- |
| 로그인 유지 기간 | 30일 | 앱 재실행 시 자동 로그인 |
| 액세스 토큰 만료 | 리프레시 토큰으로 자동 갱신, 유저에게 미노출 | - |
| 리프레시 토큰 만료 | 강제 로그아웃 → Onboard-01 | 별도 안내 모달 없음 |
| 세션 만료 중 API 호출 | 기록 작성 중 세션이 만료된 경우, 임시저장 로직을 태워 로컬에 보존한 뒤 재로그인 시 복원 | - |

### 3-4. 로그아웃

- 확인 모달 필수 → '로그아웃' 클릭 시 세션 파기, Onboard-01 전환
- 로컬 캐시(임시저장분) 전량 삭제

### 3-5. 회원 탈퇴

- 탈퇴 즉시 계정 및 전 데이터(기록, 사진, 리스트 등) 영구 삭제. 복구 불가
- 재가입 시 신규 가입으로 진행

## 4. 모드 정책

### 4-1. 모드의 정의

모드는 **반려동물과의 사별 여부**를 나타내는 계정 단위 상태값이며, 동시에 하나만 활성화 됨

- 초기값: 온보딩 '여정 여부' 선택값
- 변경 경로: Profile-01 세그먼트 컨트롤 → 확인 모달 → 변경
- 변경 횟수 제한 없음. 사후 → 생전 되돌리기도 허용

### 4-2. 모드 전환 규칙

| 방향 | 확인 모달 본문 요지 | 전환 후 위치 |
| --- | --- | --- |
| 생전 → 사후 | 생전 모드의 완료한 버킷 리스트는 사후 메모리에서 함께 볼 수 있음 | Profile-01 유지 (홈 이동 없음) |
| 사후 → 생전 | 사후 모드의 완료한 추억 리스트는 생전 모드의 메모리에서 볼 수 없음 | Profile-01 유지 |

- 전환은 **즉시 반영**되며, 네비게이션 메뉴 4개(홈, 리스트, 메모리, 프로필) 모두에서 전환된 모드 기준으로 재구성

| 영역 | 생전 모드 | 사후 모드 |
| --- | --- | --- |
| 홈 메뉴 | 버킷 리스트 완료 기록 중 최신 5개 | 추억 리스트 완료 기록 중 최신 5개 |
| 리스트 메뉴 | 생전(버킷 리스트) 항목만 | 사후(추억 리스트) 항목만 |
| 메모리 메뉴 | 생전 기록(버킷 리스트 완료 기록)만 | 생전(버킷 리스트 완료 기록) + 사후 기록(추억 리스트 완료 기록) 모두 |
| 프로필 메뉴 | 공통 | 프로필 이미지에 날개 추가 |

### 4-3. 모드 전환 시 데이터 처리

| 데이터 | 상세 |
| --- | --- |
| 미완료 리스트 항목 | 삭제하지 않고 각 모드에 그대로 보존. 해당 모드로 복귀 시 이전 상태 그대로 노출 |
| 완료된 기록 | 생성 시점의 모드를 고정. 이후 모드가 바뀌어도 기록 소속 모드는 생성 시점의 모드를 유지 |
| 임시저장분 | 해당 항목과 함께 모드에 귀속, 보존 |

## 5. 데이터 정책

### 5-1. 엔티티 관계

| 엔티티 관계 | 관계 | 설명 |
| --- | --- | --- |
| 계정(User) ↔ 반려동물(Pet) | **1 : 1** | 계정당 반려동물 1마리 |
| 계정(User) ↔ 리스트 항목(ListItem) | **1 : N** | 계정당 여러 리스트 항목 생성 가능 / 생성 당시 모드에 귀속 |
| 계정(User) ↔ 기록(Memory) | **1 : N** | 계정당 여러 기록 생성 가능 / 생성 당시 모드에 귀속 |
| 리스트 항목(ListItem) ↔ 기록(Memory) | **1 : 1** | 리스트 항목 완료 시 기록으로 전환. 전환 후 리스트 항목에서는 삭제 |
| 기록(Memory) ↔ 사진(Photo) | **1 : 0~5** | 기록당 사진 최대 5장 첨부 가능 |

### 5-2. 생성·수정·삭제 규칙

| 대상 | 생성 | 수정 | 삭제 |
| --- | --- | --- | --- |
| 리스트 항목 | List-01-03 신규 입력 / 최초 진입 시 예시 5종 자동 생성 | 인라인 수정 (미트볼 → 수정) | 리스트 항목 미트볼(List-01-01) → 삭제 → 삭제 모달(List-01-04) → 삭제 |
| 완료된 기록 | 항목 완료 시에만 생성. 항목 없이 기록 단독 생성 불가 | Memory-02 → 수정 → List-02(EDIT) | 카드 미트볼(Memory-01-01) → 삭제 모달(Memory-01-03) → 삭제 |
| 임시저장 기록 | 임시저장분 작성 시 생성 | List-01-01 → List-02(EDIT) → 임시 저장 클릭 | 리스트 항목 미트볼(List-01-01) → 삭제 |
| 사진 | 기록 작성 화면에서만 등록 | 개별 삭제 후 재등록 | 기록 삭제 시 연동 삭제 |

### **5-3. 예시 리스트 데이터베이스**

- 최초 진입 시 모드별 예시 5종을 실제 데이터로 생성
- 유저는 이를 수정·삭제할 수 있으며, 삭제 후 재생성되지 않음
- 모드 전환 시 해당 모드의 예시 5종이 최초 1회 생성

| Table name | Data |
| --- | --- |
| Before_list_data | • ‘제일 좋아하는 간식 주기’
• ‘노을 같이 보기’
• ‘하루 동안 시간 보내기’
• ‘아이가 제일 좋아하는 장난감 사주기’
• ‘원 없이 냄새 맡게 하기’ |
| After_list_data | • ‘이별 편지 쓰기’
• ‘아이가 나한테 남긴 좋은 습관 기록해보기’
• ‘함께 찍은 사진 중 제일 좋아하는 것 고르기’
• ‘아이에게 고마웠던 순간 작성해보기’
• ‘아이가 좋아했던 산책 코스 가보기’ |

### 5-4. 데이터 보관

| 상황 | 보관 |
| --- | --- |
| 유저 능동 삭제 (항목·기록) | 모달 노출 후 삭제. 휴지통 없음 |
| 회원 탈퇴 | 즉시 영구 삭제. 복구 불가 |
| 사진 원본 | 기록 삭제 시 스토리지에서 함께 삭제 |

## 6. 입력값 정책

### **6-1. 입력값 공통 정책**

| 필드 | 필수 여부 | 길이/범위 | 제약 |
| --- | --- | --- | --- |
| 반려동물 종류 | 필수 | 강아지 / 고양이 2종 | 단일 선택, 기본 선택값 없음 |
| 반려동물 이름 | 필수 | 1~10자 | 공백·특수문자 불가. 10자 초과 시 입력 자체 차단 |
| 반려동물 나이 | 선택 | 0~99 정수 | 단위 '살'. 미입력 시 프로필에 미표시 |
| 리스트 항목명 | 필수 | 1~50자 | 공백만으로 등록 불가 |
| 기록 제목 | 필수 | 1~50자 | 기본값 = 항목명. 공백 불가(띄어쓰기 가능) |
| 기록 본문 | 필수 | 1~1,000자 | 높이 자동 확장 |
| 기록 날짜 | 필수 | 과거·현재만 가능 | 기본값 = 생성일. 직접 입력 불가, 캘린더만 |
| 사진 | 선택 | 최대 5장 | 첫 장 = 대표 이미지. 가로 1080~1200px 리사이즈 |

## 7. 기록 작성 정책

### 7-1. 진입 출처 분기

- List-02는 진입 출처를 **NEW / EDIT** 두 값으로 보유하며, 완료 시 동작이 분기

| 출처 | 진입 경로 | 완료 시 동작 | 모달 |
| --- | --- | --- | --- |
| NEW | List-01-01 항목 행 클릭 | 리스트 항목 삭제 + 메모리 카드 생성 | '기록을 메모리에 저장했어요!' (List-03-01) |
| EDIT | Memory-02 '수정' 클릭 | 기존 카드 갱신. 리스트 조작 없음 | '기록을 메모리에 저장했어요!' (List-03-01) |

### 7-2. 임시저장 정책

| 항목 | 설명 |
| --- | --- |
| 저장 단위 | 항목 1개당 임시저장본 1개. 덮어쓰기 |
| 저장 시점 | '임시 저장' 버튼 클릭 시 (자동 저장 없음) / 변경 내용 확인 모달 표출 후 저장하고 나가기 버튼 클릭 시(List-03-03) |
| 재진입 경로 | List-01-01에서 해당 항목 클릭 시, 임시저장분이 있으면 자동 프리필 |
| 파기 시점 | 기록 완료 저장 시 / 해당 리스트 항목 삭제 시7-3 |

## 8. 홈 노드 정책

| 항목 | 규칙 |
| --- | --- |
| 슬롯 수 | 5개 고정. 배경 이미지에 좌표 고정, 상단부터 1~5번 (모드 무관) |
| 노출 대상 | 상시 최신 5개 완료 기록만. 6번째부터는 가장 오래된 것이 밀려남 |

| 노드 클릭 | 기록 있음 → Memory-02 / 비어 있음 → 동작 없음 |

## 9. 공통 시스템 정책

- 현재 기능명세서에 정의되지 않은 항목으로, 전 화면에 공통 적용한다.

| 구분 | 정책 |
